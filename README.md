# steamos-fixes

> **Archived.** SteamOS 3.10 ships the HDMI 2.1 FRL and VRR fixes this
> project carried out of tree, so it is no longer needed. The repository is
> read-only and will not be updated. If you still have it installed, update
> to SteamOS 3.10 and remove it with `sudo ./steamos-fixes.sh uninstall`
> from `/var/lib/steamos-fixes/src` (or run `uninstall/uninstall.sh`). The
> `hdmi-frl` fix also retires itself when it sees the newer kernel.

Out-of-tree fixes for **stock SteamOS** (stable channel) that Valve has not
shipped yet. Built from source, surviving SteamOS A/B updates, fully
reversible, and hardware-agnostic: every fix declares which hardware it is
for and does nothing elsewhere. The first fix targets the **Valve Steam
Machine**; the framework is shared with
[ally-x20-steamos](https://github.com/cchulo/ally-x20-steamos).

> **AI-assisted.** The code, patches, tests and documentation in this
> repository were written with AI assistance (Claude) under the owner's
> direction, and are reviewed and tested by the owner on their own
> hardware. It ships a patched kernel module and a kernel command-line
> change: read what you run, and use it at your own risk.
>
> **Status: pre-release.** Nothing here has run on a Steam Machine yet;
> the first on-device checks are listed in
> [`STEAMOS-FIXES-PLAN.md`](STEAMOS-FIXES-PLAN.md) §7.

**New here? Read the [user guide](docs/user-guide.md).**

## Install and update

Desktop Mode, Konsole. Clone, check out the newest release, read what you
are about to run as root, then install:

```sh
git clone https://github.com/cchulo/steamos-fixes.git
cd steamos-fixes
git checkout "$(git tag -l 'v*' --sort=-version:refname | head -n1)"   # newest release
sudo ./steamos-fixes.sh install
```

`install` copies the release to `/var/lib/steamos-fixes/src`, pins the
release signing key, applies every fix that applies to this machine and
prints a status. Reboot when it asks.

Update to the newest release from the installed copy:

```sh
cd /var/lib/steamos-fixes/src
sudo ./steamos-fixes.sh self-update --check   # is there a new release?
sudo ./steamos-fixes.sh self-update           # fetch, verify the signature, re-apply
```

Check: `sudo ./steamos-fixes.sh status`. Remove: `sudo ./steamos-fixes.sh uninstall`.

## Fixes

| Fix | Hardware | What it does | Docs |
|---|---|---|---|
| `hdmi-frl` | native HDMI port of an amdgpu device (Steam Machine) | HDMI 2.1 FRL instead of TMDS: 4K120 at up to 12-bit or 4K144 at 10-bit, 4:4:4, HDR, **with VRR** (a one-line amdgpu patch); no DP→HDMI dongle needed | [docs/fixes/hdmi-frl.md](docs/fixes/hdmi-frl.md) |

Expected to be superseded by Valve's next stable kernel: `7.2.10-valve1`
enables FRL by default and carries the VRR fix. The fix retires itself when
it sees such a kernel.

## Principles

- **Only add files, never edit stock ones.** Drop-ins with a
  `steamos-fixes` marker in their name, recorded in a manifest. Two
  documented exceptions (the slot's `grub.cfg`, regenerated by SteamOS's own
  `update-grub` from our `/etc/default/grub.d` drop-in and saved first, and
  the RAUC handler registration) are restored byte-for-byte on uninstall.
- **Nothing under `/usr`, ever.** `steamos-readonly` is never toggled; a
  policy test fails the build if the string appears. No `depmod`, no
  `mkinitcpio` against the root filesystem.
- **Survives updates, measured not assumed.** A SteamOS update prunes `/etc`
  to a keep list; ours is generated. State lives in
  `/var/lib/steamos-fixes`, a symlink into the shared `/home` partition.
  A RAUC hook and a boot service re-apply what an update dropped.
- **Never a broken boot, never a blocked update.** Patched modules load only
  for the exact kernel they were built for; a new SteamOS kernel boots with
  stock modules and the affected fix reports `degraded` and why, until a
  release asset or an on-device build exists. `update-policy block` is an
  opt-in.
- **Reversible from any state.** The standalone POSIX uninstaller works from
  a partial manifest, mid-update, from the other slot or recovery media, and
  refuses a deny-list of paths even if the manifest is crafted.

## CLI

```
steamos-fixes.sh [--root <dir>] [--dry-run] [--verbose] [--yes] [--i-know] <command>
```

| Command | Purpose |
|---|---|
| `install` | clone to `/var/lib/steamos-fixes/src`, pin keys, `apply`, `status` |
| `apply [--slot <mount>] [--only <c>] [--missing-only] [--verify-only]` | (re)apply fixes here or into a mounted slot; idempotent |
| `status [--json] [--verbose]` | per fix `active` / `degraded` / `stock` / `superseded` / `n/a` with a reason |
| `probe [--notify]` | "has SteamOS caught up?" per fix |
| `rebuild [--kver <v>]` | fetch or build the patched kernel modules (cache → release asset → container build) |
| `self-update [--channel stable\|beta] [--check] [--rollback]` | signed-tag update of the checkout, migrations, re-apply |
| `hdmi-frl frl [--without-vrr] \| tmds \| status` | the HDMI 2.1 fix: switch the link mode, show what runs |
| `update-policy show\|degrade\|block [--once]` | what an update does if modules cannot be built (default: degrade) |
| `boot-entry show\|set\|clear\|apply\|restore` | the early-initrd exception (module override for initramfs-loaded modules) |
| `audit [--json]` | manifest vs filesystem: modified, missing, unexpected |
| `uninstall [--superseded] [--component <c>] [--force] [--keep-state] [--reboot]` | remove what we added, restore saved originals |
| `components`, `version`, `help` | introspection |

`boot`, `notify` and `rauc-handler` are internal entry points for the systemd
units and RAUC. Every command accepts `--root <dir>` and runs unchanged
against a fixture tree, which is how the test suite works.

## Repository layout

```
steamos-fixes.sh      CLI dispatcher            lib/          common, manifest, probes, component, slots, rauc, grub, modules, selfupdate, status, notify, retired
cmd/                  one file per command      components/   framework: modules, update      fixes/<name>/   one directory per fix
overlay/              files installed on the device (manifest-tracked)   uninstall/   standalone POSIX uninstaller + EFI clean-up
patches/kernel/       NNNN-*.patch + modules-<fix>.list                  build/       Containerfile, build-modules.sh, kernels.txt, kernel-sources.md
keys/                 release signing key       migrations/   idempotent self-update migrations   tests/   bats suites, fixtures
vm/                   QEMU/KVM harness (Linux host / CI)                 docs/        documentation (index: docs/README.md)
.github/workflows/    test.yml (lint + unit), build-modules.yml (release assets), vm-tests.yml
```

## Developing

```sh
make check      # shellcheck + shfmt + SPDX headers, then bats
make test       # tests only
./steamos-fixes.sh --root /tmp/fixture status   # everything runs against a fixture root
```

Requirements on a dev host: bash (3.2 is enough; SteamOS has 5), `bats-core`,
`shellcheck`, `shfmt`, `jq`, `zstd`, `cpio`. Compiling kernel modules and the
VM runs need an x86 Linux host with podman and KVM
([docs/vm-testing.md](docs/vm-testing.md)). Read
[docs/contributing.md](docs/contributing.md) before opening a PR; adding a
fix is described there and in [docs/architecture.md](docs/architecture.md).
