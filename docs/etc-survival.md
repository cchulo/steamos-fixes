# /etc survival across SteamOS updates

Which of our `/etc` drop-ins does a SteamOS A/B update carry to the new
slot on its own, which only because of our keep list, and which does the
RAUC post-install hook or the boot service have to restore (plan §4.3,
§7 step 3)? This page holds the **measured** answer. Nothing here may be
filled in from assumptions; the expectation column comes from reading
`steamos-customizations` 3.9 and is there to be confirmed or refuted.

## Expectation (from the scripts, to be confirmed)

`holo-sync-var all` prunes the `/etc` overlay upper directory to
`/usr/lib/rauc/atomic-update-keep.conf` + `/etc/atomic-update.conf.d/*.conf`.
beaglemoo measured on 3.9.5 that `/etc/default/grub.d/hdmi-frl.cfg` was
dropped without a keep-list entry, which matches.

| path | owner | expected | why |
|---|---|---|---|
| `/etc/atomic-update.conf.d/steamos-fixes.conf` | update | kept | default keep list: `/etc/atomic-update.conf.d/*.conf` |
| `/etc/steamos-fixes/**` (loader, staged modules) | modules | kept **only with our keep list** | not on the default list |
| `/etc/modprobe.d/steamos-fixes-modules.conf` | modules | kept only with our keep list | not on the default list |
| `/etc/default/grub.d/steamos-fixes-hdmi-frl.cfg` | hdmi_frl | kept only with our keep list; honoured by `holo-finalize-install`'s `update-grub` | beaglemoo's finding |
| `/etc/systemd/system/steamos-fixes*.service` (+ `.wants` links) | update | kept | default keep list |
| `/etc/systemd/user/steamos-fixes-notify.service` (+ `.wants` link) | update | kept only with our keep list | `/etc/systemd/user` is not on the default list |
| `/etc/rauc/system.conf` (our block) | update | **dropped** (by design) | `holo-sync-var` deletes `etc/upper/rauc`; post-install re-registers in the new slot |
| `/var/lib/steamos-fixes` (symlink) | all | carried by the var rsync; re-created by `apply --slot` | |
| `/efi/EFI/steamos/grub.cfg` (regenerated with our argument) | hdmi_frl | regenerated by Valve with the kept drop-in | step 3 of the stock handler |
| `/efi/EFI/steamos/steamos-fixes-modules.img` + initrd token | modules | **not carried** (per-slot efi, regenerated grub.cfg) | restored by `apply --slot` in post-install |

## How to measure

On the Steam Machine (no VM needed), on a clean install:

```sh
sudo vm/guest/measure-etc-survival.sh before        # plants markers, records sha256 of /etc
sudo steamos-update && sudo reboot                   # a real update (beta opt-in if stable has none)
sudo vm/guest/measure-etc-survival.sh after > etc-survival-run.md
sudo vm/guest/measure-etc-survival.sh cleanup
```

Run it twice: once with nothing of ours installed (what SteamOS does by
itself) and once after `steamos-fixes.sh install`, passing
`--restored <file>` with the paths the hook/service logged as re-applied
(`journalctl -u steamos-fixes -b`, `state/status.json` → `reapplied`).
Paste the marker rows into the table below and record the builds. Boot the
new slot once with `systemd.mask=steamos-fixes.service` to see the state
before our boot service repairs anything.
